라이브러리는 브랜드를 지니지 않습니다. 컴포넌트는 토큰을 읽고, 토큰은 커스텀 프로퍼티를 읽고, 프로퍼티는 빌드가 선언한 것입니다. 사이트, 마크, 이름, 색, 글꼴은 각각 한 곳의 값 하나입니다. 다른 조직을 위한 빌드는 이쪽의 것을 하나도 지니지 않습니다.

## 이 사이트

이 문서는 환경 변수 `BRAND` 에서 만들어집니다. `brand.ts` 는 그것을 한 번 읽고, 이름, 조직, 인라인 SVG 로서의 마크, 그 마크에서 이끌어 낸 data URI 파비콘, 링크, 그리고 브랜드가 가지고 있을 때의 프레임워크 링크를 공개합니다.

```bash
BRAND=lux pnpm build
```

페이지의 문자열은 모두 그 모듈에서 옵니다. 헤더, 푸터, 제목, 그리고 지금 읽고 있는 페이지입니다. 페이지는 이름 대신 `brand.name` 을 적습니다. 코드 예제는 그 빌드가 설명하는 패키지로 다시 쓰입니다. 카탈로그는 본가의 이름을 지닌 모듈이나 멤버를 다른 브랜드용 빌드에서 떨어뜨립니다. 상대 브랜드의 `index.html` 에는 이쪽의 흔적이 남지 않습니다.

## 정체

`@hanzo/ui/product/pure` 는 마크가 그려지는 브랜드 세트 `HANZO`, `LUX`, `ZOO`, `PARS` 와, id 에 정체를 답하는 `resolveBrand` 를 공개합니다. 없으면 본가로 돌아갑니다.

```ts
import { BRANDS, resolveBrand, type BrandIdentity } from '@hanzo/ui/product/pure'

const brand: BrandIdentity = resolveBrand('lux')
brand.name     // 'Lux'
brand.viewBox  // '0 0 100 100'
brand.content  // the mark's inner SVG, drawn in currentColor
brand.href     // 'https://lux.network'
```

마크는 `currentColor` 를 쓰므로 하나의 에셋이 두 테마에 쓰입니다. 자기 채움이 있는 마크는 `fullColor` 라고 합니다. 프로덕트 층의 움직이는 로고는 정체를 prop 으로 받습니다.

```tsx
import { AnimatedLogo } from '@hanzo/ui/product'
import { LUX } from '@hanzo/ui/product/pure'

<AnimatedLogo surface="Cloud" brand={LUX} />
```

## 색과 글꼴

브랜드는 캐스케이드 뒤에서 같은 커스텀 프로퍼티를 선언해 정체를 다시 맞춥니다. 그중 둘은 사람이 움직이는 모습의 노브이기도 합니다. 가장 좁은 의견이 축마다 이깁니다. 설치, 그다음 조직, 그다음 사람입니다.

```css
:root {
  --primary: #808000;
  --accent: #808000;
  --font-sans-provided: 'Inter', ui-sans-serif, system-ui, sans-serif;
}
```

`--font-sans` 가 아니라 `--font-sans-provided` 입니다. 패키지 자신의 묶음은 캐스케이드 레이어 안에 있으므로, 호스트의 레이어 없는 선언은 특이성에 상관없이 이깁니다. 호스트의 글꼴이 실제로 칠해지는 글꼴이 되는 이유입니다.

`@hanzo/appearance` 의 조직 층은 서버의 한 행에서 같은 노브를 나릅니다. `current({ install, org, orgId })` 는 어떤 기기 위의 조직에 있는 사람이 보아야 할 것을 풉니다. `bootScript({ org, base })` 는 설치와 조직의 기본값을 head 스크립트에 구우므로, 첫 페인트부터 이미 브랜드 위에 있습니다.

## 남는 것

패키지는 npm 이름을 유지합니다. 코드 예제의 일은 붙여 넣어지는 것입니다. 그 이름과, 그것이 만들어진 프레임워크 둘은 다른 브랜드용 빌드에서도 아직 말해집니다.
