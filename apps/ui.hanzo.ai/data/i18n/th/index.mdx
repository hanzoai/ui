{brand.name} คือไลบรารีคอมโพเนนต์ของ {brand.org} ทุกคอมโพเนนต์เรนเดอร์ผ่าน
[@hanzo/gui](https://gui.hanzo.ai) เอนจินสไตล์สำหรับ React และ React Native
ที่รับสไตล์เป็นพร็อพแล้วคอมไพล์เป็น CSS แบบอะตอมบนเว็บ เพราะเอนจินข้ามแพลตฟอร์ม
ไลบรารีจึงข้ามแพลตฟอร์มด้วย `Switch` ตัวเดียวกันเป็น `div` ในเบราว์เซอร์
และเป็นวิวเนทีฟบนโทรศัพท์

ที่นี่ไม่มีบิลด์ของคลาสยูทิลิตี ไม่มี Tailwind ไม่มีปลั๊กอิน PostCSS
ไม่มีพื้นฐาน Radix อยู่ใต้คอมโพเนนต์ ไม่มีรีจิสทรี ไม่มี `components.json`
และไม่มี CLI ที่คัดลอกซอร์สเข้าที่เก็บของคุณ ติดตั้งแพ็กเกจแล้วนำเข้าจากมัน

## ติดตั้งแล้วเรนเดอร์

```bash
pnpm add @hanzo/ui @hanzo/gui
```

```tsx title="main.tsx"
import { Hanzo, Button } from '@hanzo/ui'

export default function App() {
  return (
    <Hanzo>
      <Button>Ship</Button>
    </Hanzo>
  )
}
```

นั่นคือการตั้งค่าทั้งหมด `Hanzo` คือรูท และมันถือสามสิ่งที่เคยเป็นงานของแต่ละแอป
ค่าคอนฟิกของ gui ที่โทเคนคลี่กับมัน สไตล์ชีต และธีม ไม่มี CSS ให้นำเข้า
และไม่มีตัวสร้างให้รัน ชีตเกิดขึ้นตอนเผยแพร่แพ็กเกจ ด้วยการเรนเดอร์ทุกคอมโพเนนต์
แล้วเก็บ CSS ที่การเรนเดอร์นั้นผลิต ดังนั้นการเพนต์ครั้งแรกและทุกการเรนเดอร์บนเซิร์ฟเวอร์
มีกฎของตัวเองอยู่แล้ว

สิ่งเดียวที่โฮสต์ยังทำคือบอกตัวรวมว่า `react-native` หมายถึง `react-native-web`
เป็นนามแฝงเดียว และแต่ละหน้าของโฮสต์ใน [การติดตั้ง](/docs/installation)
บอกว่ามันไปอยู่ที่ไหน

## สไตล์คือพร็อพ

สไตล์เป็นพร็อพบนคอมโพเนนต์ และสไตล์ที่ตอบสนองคือพร็อพเดียวกันใต้คีย์จุดตัด

```tsx
import { Button, Text, XStack, YStack } from '@hanzo/ui'

<YStack gap="$4" p="$5" $md={{ p: '$8' }}>
  <Text fontSize="$5" color="$color11">
    Balance
  </Text>
  <XStack gap="$2">
    <Button>Send</Button>
    <Button variant="outline">Receive</Button>
  </XStack>
</YStack>
```

จุดตัดเป็นความกว้างขั้นต่ำที่เริ่มจากมือถือ `$sm` 640, `$md` 768,
`$lg` 1024, `$xl` 1280 ค่าที่ขึ้นต้นด้วย `$` เป็นโทเคน — สี ขนาด
ขั้นของบันไดระยะ — และคลี่กับธีม ดังนั้น `$background` เป็นคนละสีในสว่างและมืด
โดยจุดเรียกไม่ต้องรู้ ขนาดแบบอักษรเป็นโทเคนเสมอ ไม่เคยเป็นตัวเลข
`fontSize="$3"` ไม่ใช่ `fontSize={14}` คนหนึ่งตั้งสเกลตัวอักษรของตัวเองได้
และบันได `$n` เคลื่อนตาม เลข 14 ที่เขียนตายตัวทำไม่ได้
[ธีม](/docs/theming) มีบันไดเหล่านั้น

## การจัดวาง

สแตกเป็น flex `XStack` วางเป็นแถว `YStack` วางเป็นคอลัมน์
และทั้งคู่รับ `gap`, `items` และ `justify` กริดเป็นกริด CSS จริง
ที่ `@hanzo/ui/grid` รางของมันมาจากกล่อง ไม่ใช่จากลูก — ดู [กริด](/docs/grid)

## อะไรอยู่ที่ไหน

| การนำเข้า | คืออะไร |
| --- | --- |
| `@hanzo/ui` | API คอมโพเนนต์ — ทุกพื้นฐาน สแตก สเกลตัวอักษร และ `Hanzo` |
| `@hanzo/ui/product` | ชั้นแอป แผนภูมิ โครมของหน้า ป้ายสถานะ แผงรายละเอียด ตัวสลับธีม |
| `@hanzo/ui/blocks` | เนื้อหาเป็นข้อมูล และตัวเรนเดอร์ที่วาดมัน |
| `@hanzo/ui/grid` | `Grid` และ `Cell` เว็บเท่านั้น |
| `@hanzo/ui/product/pure` | กฎที่ชั้นผลิตภัณฑ์รันบนนั้น โดยไม่มีคอมโพเนนต์ติดมา |
| `@hanzo/ui/css` | `substitute` สำหรับเทสที่ DOM ไม่มีคาสเคดตอบไม่ได้ |
| `@hanzo/ui/next` | ตัวหุ้มของ Next ที่ตั้งนามแฝงเว็บให้ตัวรวมทั้งสอง |

หน้าแคตตาล็อกของไซต์นี้ — [คอมโพเนนต์](/ui), [บล็อก](/blocks),
[ผลิตภัณฑ์](/product) — อ่านจากแพ็กเกจเอง แต่ละหน้าเรนเดอร์ตัวอย่างของโมดูล
ข้างซอร์ส และอ้างชนิดของมัน

## คำถาม

**ต้องใช้ Tailwind ไหม** ไม่ คอมโพเนนต์รับพร็อพสไตล์ และตัวตนคือคุณสมบัติกำหนดเองของ CSS ธรรมดา ถ้าแอปมาพร้อมสตริงของคลาส `Box`, `sx` และ `css` อ่านผ่าน `tw` แล้วเปลี่ยนเป็นพร็อพเดียวกัน ไม่มีอะไรไปถึง DOM ในฐานะคลาสที่แพ็กเกจไม่ได้กำหนด

**นี่คือการคัดลอกแล้ววางไหม** ไม่ ติดตั้งแพ็กเกจแล้วนำเข้าจากมัน คอมโพเนนต์ถูกกำหนดเวอร์ชันไปกับแพ็กเกจ และแผนที่ส่งออกคือทางที่ซับพาธคลี่ผ่าน ดังนั้นการนำเข้าที่ลึกยังใช้ได้ข้ามแพตช์

**เฟรมเวิร์กใด** ตัวเรนเดอร์ React 19 ใดก็ได้ เมื่อตัวรวมรู้จักนามแฝง `react-native` มีหน้าสำหรับ [Vite](/docs/installation/vite), [Next](/docs/installation/next), [One](/docs/installation/one), [Expo](/docs/installation/expo) และ [Tauri](/docs/installation/tauri)
