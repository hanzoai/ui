title: Expo и React Native
description: Тот же импорт, и псевдоним не нужен. Metro уже говорит на react-native.
---

Библиотека рисует через @hanzo/gui, а он в первую очередь React Native: стек — это `View`, текст — `Text`, стилевой проп — стиль. Те же компоненты, что рисуют `div` на вебе, рисуют здесь нативное представление, и токены темы, шкала интервалов и лестница кегля значат одно и то же на обеих сторонах.

## Установка

```bash
pnpm create expo-app@latest my-app
cd my-app
pnpm add @hanzo/ui @hanzo/gui
```

Настройки сборщика нет. Псевдоним `react-native`, который ставят веб-хосты, нужен, чтобы веб-сборщик прочитал нативный пакет. Metro — нативный сборщик и читает пакет как написано. Импорт таблицы стилей, который несёт корень, под Metro на нативе ничего не делает, а на Expo web применяется.

## Смонтируйте корень

```tsx title="app/_layout.tsx"
import { Hanzo } from '@hanzo/ui'
import { Stack } from 'expo-router'

export default function Layout() {
  return (
    <Hanzo>
      <Stack />
    </Hanzo>
  )
}
```

## Что остаётся на вебе

`@hanzo/ui/grid` рендерит `div` с `display: grid`, и ни того ни другого на React Native нет — у Yoga нет алгоритма сетки, — поэтому сетка выходит на собственном subpath, а не из корневого barrel. Раскладывайте там через `XStack` и `YStack`. Нативный движок сетки меняет один этот файл и ни одного места вызова. Графики в `@hanzo/ui/product` рисуют встроенный SVG и меряют контейнер через `ResizeObserver`, так что сегодня это тоже веб-компоненты.

Области касания держат пол в 44 пункта через `hitSlop`, никогда через padding: коробка контрола одного размера на обеих платформах, а касаемая область — нет.
