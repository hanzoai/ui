---
title: Бренд
description: Бренд решается один раз, во время сборки, и доходит до каждой поверхности как значение. Ничто в компонентах не называет дом.
---

Библиотека не несёт бренда. Компонент читает токен, токен читает пользовательское свойство, а свойство — то, что объявила сборка. Сайт, знак, имя, цвет и гарнитура — каждое одно значение в одном месте, поэтому сборка для другой организации не несёт ничего от этой.

## Этот сайт

Эта документация собирается из переменной окружения `BRAND`. `brand.ts` читает её один раз и публикует имя, организацию, знак как встроенный SVG, favicon как data URI, выведенный из этого знака, ссылки и ссылку на фреймворк, если она у бренда есть.

```bash
BRAND=lux pnpm build
```

Каждая строка на странице приходит из этого модуля — шапка, подвал, заголовки и страницы, которые вы читаете: они пишут `brand.name`, а не имя. Примеры кода переписываются на пакет, который документирует сборка, а каталог выбрасывает любой модуль или член, несущий имя дома, из сборки для другого бренда, так что `index.html` другого бренда не содержит следа этого.

## Идентичность

`@hanzo/ui/product/pure` публикует набор брендов, из которого рисуются знаки, — `HANZO`, `LUX`, `ZOO`, `PARS` — и `resolveBrand`, который отвечает на id идентичностью и откатывается к дому.

```ts
import { BRANDS, resolveBrand, type BrandIdentity } from '@hanzo/ui/product/pure'

const brand: BrandIdentity = resolveBrand('lux')
brand.name     // 'Lux'
brand.viewBox  // '0 0 100 100'
brand.content  // the mark's inner SVG, drawn in currentColor
brand.href     // 'https://lux.network'
```

Знаки используют `currentColor`, поэтому один ассет служит обеим темам; знак, который несёт собственные заливки, говорит `fullColor`. Анимированный логотип в слое продукта принимает идентичность пропом:

```tsx
import { AnimatedLogo } from '@hanzo/ui/product'
import { LUX } from '@hanzo/ui/product/pure'

<AnimatedLogo surface="Cloud" brand={LUX} />
```

## Цвета и гарнитура

Бренд перенастраивает идентичность, объявляя те же пользовательские свойства позже в каскаде. Два из них — ещё и регуляторы внешнего вида, которые двигает человек, и самое узкое мнение побеждает по каждой оси: сначала установка, потом организация, потом человек.

```css
:root {
  --primary: #808000;
  --accent: #808000;
  --font-sans-provided: 'Inter', ui-sans-serif, system-ui, sans-serif;
}
```

`--font-sans-provided`, а не `--font-sans`: собственная привязка пакета сидит в слое каскада, поэтому объявление хоста вне слоя побеждает при любой специфичности. Именно поэтому красится гарнитура хоста.

Слой организации в `@hanzo/appearance` несёт те же регуляторы из строки на сервере. `current({ install, org, orgId })` разрешает, что должен видеть человек в организации на устройстве, а `bootScript({ org, base })` запекает умолчания установки и организации в скрипт в head, так что первая отрисовка уже в бренде.

## Что остаётся

Пакет сохраняет имя в npm, потому что пример кода должен вставляться как есть. Это имя и фреймворк, на котором пакет собран, — две вещи, которые сборка для другого бренда всё ещё произносит.
