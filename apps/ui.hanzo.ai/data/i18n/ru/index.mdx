{brand.name} — библиотека компонентов {brand.org}. Каждый компонент рисуется через [@hanzo/gui](https://gui.hanzo.ai), движок стилей для React и React Native: стили приходят пропами и на вебе собираются в атомарный CSS. Движок кроссплатформенный, поэтому библиотека тоже: один и тот же `Switch` в браузере становится `div`, а на телефоне — нативным представлением.

Сборки на утилитарных классах здесь нет. Ни Tailwind, ни плагина PostCSS, ни примитива Radix под компонентом, ни реестра, ни `components.json`, ни CLI, которая копирует исходники в репозиторий. Ставите пакет и импортируете из него.

## Установить и отрисовать

```bash
pnpm add @hanzo/ui @hanzo/gui
```

```tsx title="main.tsx"
import { Hanzo, Button } from '@hanzo/ui'

export default function App() {
  return (
    <Hanzo>
      <Button>Ship</Button>
    </Hanzo>
  )
}
```

Это вся настройка. `Hanzo` — корень, и он несёт три вещи, которые раньше были делом каждого приложения: конфиг gui, относительно которого разрешаются токены, таблицу стилей и тему. CSS импортировать не нужно и генератор запускать не нужно — таблица рождается при публикации пакета: каждый компонент рендерится, и CSS этого рендера собирается, так что первая отрисовка и каждый серверный рендер уже приходят со своими правилами.

Единственное, что хост всё ещё делает, — говорит сборщику, что `react-native` означает `react-native-web`. Это один псевдоним, и каждая страница хоста в разделе [Установка](/docs/installation) показывает, куда он ставится.

## Стиль — это пропы

Стиль — это проп компонента, а отзывчивый стиль — тот же проп под ключом брейкпоинта.

```tsx
import { Button, Text, XStack, YStack } from '@hanzo/ui'

<YStack gap="$4" p="$5" $md={{ p: '$8' }}>
  <Text fontSize="$5" color="$color11">
    Balance
  </Text>
  <XStack gap="$2">
    <Button>Send</Button>
    <Button variant="outline">Receive</Button>
  </XStack>
</YStack>
```

Брейкпоинты — минимальные ширины, mobile-first: `$sm` 640, `$md` 768, `$lg` 1024, `$xl` 1280. Значение, которое начинается с `$`, — токен: цвет, размер, ступень шкалы интервалов. Он разрешается относительно темы, поэтому `$background` — разный цвет в светлой и тёмной теме, и месту вызова об этом знать не нужно. Кегль всегда токен, никогда число: `fontSize="$3"`, а не `fontSize={14}`. Человек может задать собственную шкалу, и лестница `$n` поедет вместе с ней; зашитые 14 — нет. Шкалы — на странице [Темы](/docs/theming).

## Раскладка

Стеки — это flex. `XStack` раскладывает в ряд, `YStack` — в колонку, и оба принимают `gap`, `items` и `justify`. Сетка — настоящая CSS-сетка, в `@hanzo/ui/grid`: её дорожки задаёт контейнер, а не дети. См. [Сетка](/docs/grid).

## Что где лежит

| Import | Что это |
| --- | --- |
| `@hanzo/ui` | API компонентов — каждый примитив, стеки, шкала кегля и `Hanzo`. |
| `@hanzo/ui/product` | Слой приложения: графики, хром страницы, метки состояния, панели подробностей, переключатель темы. |
| `@hanzo/ui/blocks` | Содержимое как данные и отрисовщики, которые его рисуют. |
| `@hanzo/ui/grid` | `Grid` и `Cell`, только веб. |
| `@hanzo/ui/product/pure` | Правила, на которых работает слой продукта, без прикреплённого компонента. |
| `@hanzo/ui/css` | `substitute`, для тестов, на которые DOM без каскада ответить не может. |
| `@hanzo/ui/next` | Обёртка Next, которая ставит веб-псевдонимы для обоих сборщиков. |

Страницы каталога этого сайта — [Компоненты](/ui), [Блоки](/blocks), [Продукт](/product) — читаются из самого пакета: каждая рендерит примеры модуля рядом с исходником и цитирует его типы.

## Вопросы

**Нужен ли Tailwind?** Нет. Компоненты принимают стилевые пропы, а идентичность — пользовательские свойства CSS. Если приложение приходит со строками классов, `Box`, `sx` и `css` читают их через `tw` и превращают в те же пропы; в DOM не попадает класс, которого пакет не задал.

**Это копирование?** Нет. Ставите пакет и импортируете из него. Компоненты версионируются вместе с пакетом, а карта exports — то, через что разрешается subpath, поэтому глубокий импорт переживает патчи.

**Какие фреймворки?** Любой рендерер React 19, как только сборщик знает псевдоним `react-native`. Есть страницы для [Vite](/docs/installation/vite), [Next](/docs/installation/next), [One](/docs/installation/one), [Expo](/docs/installation/expo) и [Tauri](/docs/installation/tauri).

**Можно ли использовать коммерчески?** Да. Apache-2.0 или MIT, на ваш выбор.
