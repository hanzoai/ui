लाइब्रेरी @hanzo/gui से रेंडर होती है, जो पहले React Native है: स्टैक एक
`View` है, पाठ `Text` है, और स्टाइल प्रॉप एक स्टाइल है। इसलिए वही
कंपोनेंट जो वेब पर `div` खींचते हैं यहाँ नेटिव व्यू खींचते हैं, और थीम
टोकन, अंतर की सीढ़ी और अक्षर की सीढ़ी दोनों पर एक ही अर्थ रखते हैं।

## स्थापित करें

```bash
pnpm create expo-app@latest my-app
cd my-app
pnpm add @hanzo/ui @hanzo/gui
```

कोई बंडलर सेटिंग नहीं। वेब होस्ट जो `react-native` एलियास लगाते हैं वह
वेब बंडलर को नेटिव पैकेज पढ़ने देता है; Metro नेटिव बंडलर है, और उसे जैसे
लिखा है वैसे पढ़ता है। रूट जो स्टाइलशीट आयात लेकर चलता है वह नेटिव पर
Metro के नीचे कुछ नहीं करता और Expo वेब पर लागू होता है।

## रूट लगाएँ

```tsx title="app/_layout.tsx"
import { Hanzo } from '@hanzo/ui'
import { Stack } from 'expo-router'

export default function Layout() {
  return (
    <Hanzo>
      <Stack />
    </Hanzo>
  )
}
```

## जो वेब पर रहता है

`@hanzo/ui/grid` `display: grid` वाला `div` रेंडर करता है, और दोनों React
Native पर हैं ही नहीं — Yoga में ग्रिड का एल्गोरिथ्म नहीं — इसलिए यह रूट
बैरल पर नहीं, अपने सबपाथ पर शिप होता है। वहाँ `XStack` और `YStack` से
बिछाएँ; एक नेटिव ग्रिड इंजन उस एक फ़ाइल को बदलता है, किसी कॉल साइट को
नहीं। `@hanzo/ui/product` के चार्ट इनलाइन SVG खींचते हैं और अपने कंटेनर
को `ResizeObserver` से नापते हैं, इसलिए वे भी आज वेब कंपोनेंट हैं।

टच टारगेट 44 पॉइंट की न्यूनतम सीमा `hitSlop` से पूरी करते हैं, पैडिंग से
कभी नहीं, इसलिए नियंत्रण का बॉक्स दोनों प्लेटफ़ॉर्म पर एक ही आकार का है
और उसका छूने योग्य क्षेत्र नहीं।
